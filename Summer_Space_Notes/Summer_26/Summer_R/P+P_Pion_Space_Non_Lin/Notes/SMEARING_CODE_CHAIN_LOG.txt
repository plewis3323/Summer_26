There are TWO distinct families of "smearing" code in Blair's area:

  (A) PRODUCTION smearing  -- runs inside the Fun4All / pi0-tower-by-tower
      reconstruction; this is the smearing that actually feeds the data/MC
      comparison and the physics result.

  (B) STANDALONE TOY smearing -- self-contained ROOT macros used for quick
      cross-checks of resolution -> mass-width and of unfolding bias. Not part
      of the production result.

================================================================================
 PART 2 -- FRAMEWORK / SYSTEM LAYOUT
================================================================================

The production smearing is NOT one program -- it is three stages that hand a
single ROOT file (the TF1 parameter file) and a set of histograms down a chain:

  STAGE 1  PARAMETERISE  (mass_plot.C)           --> function_compare_wide.root
  STAGE 2  APPLY in reco (pi0EtaByEta.cc)        --> caloana ...root (h_m_pt_smear*)
  STAGE 3  EXTRACT/COMPARE (smear_compare.C)     --> mass/width PDFs + .root

The bridge between stages is the FILE, not a function call:
   - Stage 1 WRITES the TF1s into function_compare_wide.root.
   - Stage 2 READS that same file at Init (hard-coded path, pi0EtaByEta.cc:207)
     and Eval()'s the TF1 at each photon's energy to get sigma(E).
   - Stage 3 READS the histograms Stage 2 produced.

The "6 smear indices" decode as 3 resolution MODELS x 2 (with/without an extra
0.08 constant term), set in smearPhot() via base_smear_idx = idx%3 and
add_extra_const = idx>=3. The three models are global-minimum, cE=0.08, cE=0.05.

Physics meaning of the smear: MC clusters are already at MC resolution; the TF1s
hold the QUADRATURE EXTRA  sqrt(reso_model^2 - reso_fit^2)  needed to push MC up
to the (worse) data resolution, applied multiplicatively in energy and additively
in (eta,phi).
